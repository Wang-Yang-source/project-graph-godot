## 使用

在 Project Graph 中选择“文件 → 打开”，打开本目录的 `.prg`，先“另存为”自己的副本。双击节点改写，选中主题按 Tab 增加子主题，F2 编辑。标题、说明与来源也都是可修改的文本节点。长篇证据建议拆成节点，避免挤进同一个方块。

每份模板包含 21 个文本节点和 16 条连线。中心问题向右展开四个分支，每个分支包含三个提示节点。蓝、紫、青、橙分支搭配 Catppuccin Mocha 的背景与文字，留出连线和文字空间；颜色仅用于导航，内容通过标题区分。为保留示例的视觉层级，采用显式颜色，不随主题自动改色。

SVG 是根据同一份内容与坐标绘制的静态设计预览，附带画布背景；不是应用导出或运行截图。原生节点的最终高度、碰撞和连线端点由项目运行时决定。同名 PNG 来自 Godot 原生舞台的实际离屏渲染，已逐张检查文字、间距与连线；不是完整应用窗口截图。

## 实现与复用

使用 Godot MCP 的项目查询、脚本枚举/读取、编辑器脚本执行、测试脚本创建/修改、测试场景创建/打开/挂载/保存及运行控制类别。通过现有 `ProjectFile.save`、Godot `JSON.from_native` 编码属性并保存 ZIP 项目；复用现有 TextNode、LineEdge、topic_parent 和对象引用格式。没有直接读取或写入 `.tscn` 文本，没有改应用脚本或引入第三方依赖。

标准库及现有能力足以保存模板；无需引入通用导图、ZIP 或 JSON 库。SVG 使用标准 XML 图形元素表达预览，避免增加运行时渲染器。

## 用户手动验收（尚未执行）

1. 打开四份 `.prg`：应看到标题、中心问题、四个分支及每组的三个节点，文字不重叠、连线端点完整。若显示空白，检查文件加载提示与相机位置；若文字重叠，检查字体导入、固定宽度与实际节点高度。
2. 双击叶节点改写，拖动一个主题：文字可编辑，连线应跟随端点。若断线，重点检查 source/target 引用恢复；若布局移动异常，观察物理避让与相邻节点间距。
3. 选中分支按 Tab，再对一个叶节点按 Enter：应生成相应子主题或同级主题。若同级创建失败，检查 topic_parent 是否恢复；新增主题样式以现有功能为准。
4. 对改字、拖动、新增依次撤销与重做：每次完整操作应能恢复。若一次操作出现多个历史步骤，检查历史事务与物理稳定行为。
5. 另存为副本，关闭后重开：文字、颜色、关系与布局应保留。若有丢失，检查保存错误、对象 ID 和引用解析。
6. 切换深浅主题并缩放：模板采用固定 Mocha 配色，应仍可阅读；检查缩小时的文字、线条与节点边界。最终视觉效果尚未在应用中检查。
