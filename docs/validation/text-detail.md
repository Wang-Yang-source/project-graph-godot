# 缩放文字细节

复用 Godot `Label.visible_characters` 与 `TextServer.VC_CHARS_AFTER_SHAPING`，省略低于 2 个实际屏幕像素的字形；放大到 3 像素恢复，避免阈值附近反复切换。保留 Label 的可见性、尺寸、文本整形、背景、碰撞和持久化数据。概览标题不属于此缓存。

相机倍率只跨越预先排序的字体阈值时才扫描标签，使用内置 `Array.sort/bsearch`；字体、尺寸、几何或编辑对象变化使缓存失效。编辑期间恢复字形，标签离开舞台或管理节点销毁时恢复原来的字符显示状态。不需要社区库或第三方依赖；这里仅适配现有标签节点。

已通过 Headless 与 Mobile/Vulkan `text_detail_smoke`，覆盖缩小/放大、编辑切换、新节点、移出舞台、管理节点释放和数据不变。导航缓存、连线连续性、原生抗锯齿、HiDPI 与真实文档导航缓存也通过。文字焦点测试在本次修改前后的 Headless/图形后端均失败，没有混入焦点修复。

同条件隔离文字细节测量（两边使用相同的 GPU 连线网格）：981 个对象，1920×1200、UI 200%、Mobile/Vulkan、Mailbox、物理关闭、加载预热 3 秒、连续缩放采样 3 秒。绘制调用均值从 2368 降至 1887，约减少 20%；FPS 108.9→110.6，P95 12.37→12.94 ms。此次主要减少字形提交，不能声称单独显著提高 FPS。

用户手动验证：打开大文档，缩小到字形不可辨认再放大；极小字形应被省略，放大后恢复。双击文字进入编辑，应正常显示并可输入；新增节点、切换主题、改变字号以及撤销重做后也应恢复正确。失败时重点检查文字一直消失、字符只恢复一部分、Label 尺寸改变和低倍率编辑不显示。

Godot 文件读写与验证运行均使用 Godot MCP 脚本及编辑器脚本类别。未执行用户手动验收、导出 release、其他系统/GPU 和长时间内存测试。
