# 首次缩放连线碎片

打开 tutorial-main-3.1.prg 后，首次缩放可能把隐藏连线和边框按旧倍率恢复显示。相机已经更新，事件驱动节点的 set_process(true) 却要到下一帧才开始处理，产生一帧粗线、绿色团块或尖刺。

## 修复

- 连线和最小屏幕边框在视图通知中立即刷新当前倍率。
- 分组恢复可见层后，同步刷新其连线、文字边框和连线标题。
- 退出场景时只恢复可见层，不访问已退出的视口。
- 保留已有缩放网格、线宽分桶和纹理缓存。撤回此前移除网格的绕行修改。

复用 Godot 现有节点、信号和项目的几何更新方法，不引入依赖，也不另外实现通用绘制能力。

## 验证结果

真实教程、Godot 4.8 dev6、Intel Iris Xe：修改前成功捕获首次缩放的绿色团块；修改后 Mobile/Vulkan 与 Compatibility/OpenGL 各检查 80 个渲染帧通过，包括首次缩放、分组切换及反向缩放。图像检查拒绝偏离绿色连线走廊的碎片。对应测试为 tests/tutorial_zoom_artifacts_smoke.gd，需图形渲染器和 --fixture=<教程文件路径>。

lazy_zoom_mesh_smoke、zoom_stroke_cache_smoke、smooth_connections_smoke、async_preview_capture_smoke、async_preview_lifecycle_smoke 检查通过。minimum_screen_border_smoke 的调度断言已适配同步更新并通过；其既有像素采样越界日志在修改前也存在。border_screen_width_smoke 的带宽断言失败已在修改前基线确认，未在本修复中改变。教程渲染测试另有既有加载尺寸与退出时对象泄漏警告。

## 手动验证

1. 停止并重新运行当前源码，重新打开 tutorial-main-3.1.prg。
2. 定位“连线更改目标”，从首次缩放开始快速交替放大、缩小；覆盖分组预览和原始内容的切换。
3. 应保持窄绿色连线和正常边框，不出现团块、尖刺、粗线或一帧闪烁；停止缩放后也应正常。
4. 缩放中平移、拖动端点、编辑文字，再关闭文件。连线应连续跟随端点，关闭时不应出现本次恢复刷新相关的空视口报错。
5. 若仍异常，重点记录是否使用当前源码的新进程、异常首次发生的倍率、渲染后端，以及异常位于实时内容还是缩略图。其他 GPU、平台及手动操作组合尚未逐一验证。
