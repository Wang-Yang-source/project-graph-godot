# 保存后清理临时恢复副本

## 原因与实际改动

project_binary_store.gd 的 _replace_file() 在保存已有文档时，先把原文件重命名为 .prg.previous，再安装写完的临时文件。原实现成功后没有清理恢复副本，因此用户目录持续留下二进制文件。

本次只补充成功路径的清理：替换成功后删除此次事务的 .previous。替换失败时仍恢复原文件；恢复失败时保留恢复副本和新临时文件，并报告所在路径。删除失败时发出警告，因新文档已安装，不把保存报告为失败。未扫描或删除用户目录中既存的 .previous 文件。

复用现有 Godot DirAccess 文件删除及重命名 API，不新增依赖或通用文件处理实现。使用 Godot MCP 脚本读取、修改工具；文档用普通文本工具处理。

## 用户手动验证

1. 在临时目录新建项目，保存为 .prg，再修改并连续保存。目录应只保留正式 .prg，重新打开应包含最后保存的内容。失败时检查是否还产生 .previous，以及实际运行的是否为更新后的安装版。
2. 在专用测试目录让正式文档不可替换，再保存。应明确报告失败，原文档内容保持完整；回滚失败时提示恢复副本和临时文件的位置。不要用唯一的真实工作文档做此项验证。
3. 对已有 .previous 的文档重新成功保存，此次替换产生的 .previous 应被清理；其他文档的旧副本不会被批量删除。若清理权限不足，应提示警告，但正式文档仍能重新打开且包含新内容。
