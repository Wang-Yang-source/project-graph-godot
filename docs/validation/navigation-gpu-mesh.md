# 连续缩放 GPU 连线网格

上一轮 `Line2D` 屏幕宽度 shader 仍需要跨倍率区间重建原生包络。大幅缩放冷测峰值约 107 ms，预热后 P99 约 54–57 ms；隔离连线后尾部耗时明显下降。固定巨大包络会增加透明覆盖，降低普通倍率的性能，因此撤回。

本次使用 Godot 原生 `MeshInstance2D`、`ArrayMesh` 和 CanvasItem shader：从现有世界曲线生成一次三角带，UV 记录两侧偏移；顶点 shader 在 GPU 调整屏幕宽度。CPU 的固定包络保证剔除范围，实际绘制宽度随倍率调整，不绘制巨大透明条带。内置 Line2D 不提供这些自定义顶点偏移；评估的 [Antialiased Line2D](https://github.com/godot-extended-libraries/godot-antialiased-line2d) 复用纹理而保持原生多边形与 UV 生成算法，推断仍不能消除本次的包络重建。对象池也不能解决已有节点的网格更新，因此仅补这层曲线适配，不引入新库。

网格随世界几何、线宽或显示缩放变化而更新，随普通相机缩放复用。初次世界曲线刷新时预备网格，减少首次缩放尖峰。连续缩放显示 MeshInstance2D，原有 Line2D 保留世界点及拾取数据；停止缩放恢复原生纹理线条。箭头和历史数据沿用原来的逻辑。

## 测量

2026-10-03，Godot 4.8.dev6、Linux X11、Intel Iris Xe、Mobile/Vulkan、981 个对象、UI 200%、物理关闭、调试二进制。加载预热后每阶段采样 3 秒。

- 概览附近连续缩放（1920×1200、Mailbox，同样开启文字细节）：95.5→105.1 FPS，P95 16.28→13.45 ms。静止和平移帧耗时基本相同。
- 从 .025 到 1.5 的实际 Magnify 输入（VSync 关闭）：原方案冷测峰值 107.49 ms、P99 55.69 ms，预热 P99 54.42 ms；新方案最终冷测峰值 48.08 ms、P99 35.36 ms，预热 P99 23.55 ms、P95 16.67 ms。
- 桌面背景负载与引擎调试构建会产生波动。这些是本机单次对照，不能视为 release 或所有操作的 60 FPS 保证；仍有约 45 ms 的少量尖峰。

## 检查与手动验证

扩展 `zoom_stroke_cache_smoke` 验证跨倍率区间的网格资源复用、Mesh/Line2D 切换、屏幕抗锯齿覆盖、碰撞与持久数据不变、文本编辑中断及删除期间资源清理。Headless、Mobile/Vulkan、Compatibility/OpenGL 通过；单独从 HEAD 应用本修复后，导航缓存和连线连续性通过。真实文档导航缓存、HiDPI、原生抗锯齿通过。

用户手动验证：重启应用，用 Ctrl/Meta+滚轮或捏合反复从概览放大至近景，并在中途平移、选择连线、编辑节点及撤销重做。应减少跨倍率卡顿，停止后恢复原有线条。失败时重点检查曲线接头、端点、选中描边宽度、屏幕边缘剔除、连续缩放中断和双向连线是否重复显示。

使用 Godot MCP 的脚本读写、编辑器脚本与验证进程控制，未直接处理场景文本。尚未执行用户真实交互验收、导出 release、其他 GPU/系统和长期内存压力测试。
