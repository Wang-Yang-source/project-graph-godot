# 文本块原生物理碰撞

现状原因：工作区原先把 Entity 的碰撞层、掩码设为 0，冻结并从物理空间移除刚体；释放鼠标的速度固定为 0。RigidBody2D 和 CollisionShape2D 虽然存在，但没有参与物理碰撞。不能仅凭节点类型声称已有碰撞效果。

复用 Godot 4.8.dev6 原生 RigidBody2D、CollisionShape2D、PhysicsMaterial、连续碰撞检测和阻尼；不恢复已停用的脚本避让求解器，不新增依赖或通用物理实现。Godot 自带功能已满足需求，无需引入其他物理库。

实体保持在原生物理空间，碰撞层与掩码使用第 1 层，无重力、锁定旋转。共享物理材质的摩擦系数为 0.7、弹性为 0，默认线性阻尼使用 throw_damping（7）。拖拽时使用原生 KINEMATIC 冻结模式，由物理接触推开邻块；释放后恢复动态刚体，鼠标采样速度交给引擎积分和减速。关联对象仍只保留编辑几何，不参与实体碰撞。

包含关系通过原生碰撞例外排除祖先容器，避免容器把自己的内容弹出；分组移动沿用已有成员跟随机制。复用 History 的物理稳定等待，将拖拽、惯性和被推开的邻块合为一次撤销事务。没有新增物理设置界面；旧自动布局求解器的测试不能代表这套原生碰撞机制。

## 检查

通过 Godot MCP 的脚本读取/修改及编辑器脚本执行相关检查。没有直接处理场景文本，没有启动或使用 computer use 操作 Godot Editor。

新增 native_entity_physics_smoke，修改前检出物理空间缺失、碰撞关闭、无摩擦材质、接触不推开邻块、拖拽模式错误及包含碰撞例外缺失。修改后检查通过，覆盖：原生接触、惯性、阻尼、拖拽推挤、单次历史提交、撤销/重做、容器例外、分组拖拽及惯性保持成员相对位置、实际鼠标采样释放速度。

drag_target_dedup_smoke、container_connection_scope_smoke 通过。检查日志没有脚本错误。提交仅纳入这项原生物理功能及回归，不混入工作区此前的其他改动。

## 手动验收（尚未执行）

1. 退出旧实例，从用户级应用菜单重开新版。在空白区域创建两个相邻文本块，缓慢将一个推向另一个：邻块应被接触推开，不能始终叠在一起。
2. 快速拖动并松手：文本块应继续滑行一小段并逐渐停止；沿另一个块的边缘拖动，观察接触与滑动。画布无重力，不应向下掉落或自行旋转。
3. 等运动停止后按撤销：主动块与被推开的块应一起恢复；重做应恢复停止后的布局。
4. 创建包含子节点的分组，拖拽并松开分组：子节点应跟随，并保持相对位置，不应被自己的容器弹出；连线仍应跟随端点。

失败重点：仍在运行旧实例或 /usr/bin 下的旧系统安装；实体碰撞层/掩码被其他逻辑清零；拖拽释放后没有解除冻结；包含关系缺失导致子节点与容器碰撞。真实鼠标、高速拖拽、复杂嵌套图和桌面操作体验仍需人工验收。
