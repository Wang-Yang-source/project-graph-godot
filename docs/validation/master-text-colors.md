# 基础文本节点与 Mocha 颜色

对照 master 的 `TextNode.tsx` 与 `TextNodeRenderer.tsx`：基础文本节点默认透明，使用主题边框；用户填充保留原 alpha。文字低于 5 个实际屏幕像素时省略字形，透明节点以主题边框色的 20% 不透明度代替填充；放大后恢复透明。普通节点边框为 2 个世界像素，原有屏幕最小宽度适配仍保留。

Mocha 适配复用现有调色板：默认文字 Text `#cdd6f4`，边框 Surface2 `#585b70`，编辑轮廓沿用 Mauve。用主题文字色替代 master 的画布反色；完全不透明的自定义背景沿用已有对比度计算，保证文字可读。输入文字、光标与分组概览使用同一颜色规则。移除了普通节点的强制 92% 不透明显示背景。容器已有层级透明度衰减保持不变。

实现复用 Godot 的 Color、StyleBox、Label.visible_characters，以及现有文字细节阈值缓存与 Catppuccin 调色板。社区主题库无需引入：本项目已有完整 Mocha/Latte 色表，这里只补节点显示适配。没有新增依赖。填充变化只在跨越阈值时更新，不在每个缩放帧重新生成样式，不修改持久化字段。

验证：`master_text_colors_smoke.gd` 在 Headless 和 Mobile/Vulkan（Intel Iris Xe）通过，覆盖普通透明背景、Mocha 文字与边框、5px 阈值两侧、自定义透明度、不透明白色填充的文字可读性、编辑光标、分组概览、Latte 切换、新节点与细节管理器释放。阈值切换前后节点尺寸及序列化结果不变。`text_contrast_smoke.gd` 通过。图形验证截图位于 `/tmp/pg-master-text-colors.png`；独立 SubViewport 测试偶有现有 IME 屏幕坐标警告。

现有 `text_detail_smoke.gd` 的小文档缩放请求被文档导航下限限制，导致三项字形省略断言失败；移出节点时另有屏幕边框访问已脱离视口的错误。未在本次颜色修改中扩展修复范围。新回归使用足够大的文档边界，确保实际跨过 5px 阈值。工作区另有 `grid.gdshader` 尾随空白，本次暂存文件的 whitespace 检查单独执行。

手动验证：重新运行项目，选择 Mocha，创建普通文本节点。正常倍率下应透出画布或所属容器背景，文字为淡蓝白色，边框为灰紫色；给节点设置半透明颜色，透明度应保持。打开足够大的文档并缩小到文字不可读，透明节点应出现很淡的灰紫色填充；放大后文字恢复、填充消失。双击编辑与缩小进入分组概览时文字颜色应一致。失败时检查背景是否仍为近乎不透明、用户 alpha 是否被抬高、缩放后淡色背景是否残留、概览是否变成纯白字或节点尺寸是否变化。

Godot 文件读写及运行均通过 Godot MCP 的脚本修改、脚本创建、编辑器脚本执行类别。尚未执行用户手动验收、导出构建、其他系统/GPU 与长时间测试。
