# 事务开始复用同步快照

2026-10-05：指定 609 对象教程的正常输入按下同步耗时曾为 104–136 ms；裸 Stage 探针为 135.954 ms。`History.begin_transaction()` 每次重新捕获完整文档是需要单独消除的同步工作。本改动尚未证明完整 Main 的按下响应已达到 50 ms。

复用现有 Stage 文档修订号、原生 Dictionary 与 SnapshotDelta，不引入依赖或重写快照机制。只有当前快照非空、来源已同步、且修订号精确匹配时，事务开始才引用已有快照；持久属性变化仍重新捕获。非 Stage 目标保持原始捕获行为。SnapshotDelta 深复制变更记录、apply 不原地改当前快照，事务操作也不修改基线；调用者传入 clear 的值另复制，避免外部变更污染基线。

`clear(snapshot)` 不默认相信调用者提供的快照。加载流程在 `document_snapshot()` 返回后，显式传入同一时刻的 `document_revision`；修订号不匹配时仍不复用。提交包括无变化事务，均刷新当前快照和同步修订号；撤销、重做和取消在恢复完成后刷新修订号。几何呈现刷新不自动使持久快照失效。

Godot 文件通过 MCP 脚本读写与编辑器脚本执行处理；没有直接操作场景文本。History 与新 smoke 已刷新编辑器缓存后解析成功。2026-10-05 独占执行 `--headless --script res://tests/history_revision_reuse_smoke.gd`，日志 `/tmp/pg-history-revision-reuse.log` 为 `HISTORY_REVISION_REUSE: PASS`。测试覆盖捕获次数、外部属性编辑、几何刷新、无变化提交、撤销/重做/取消、任意 clear、可信加载、传值别名和非 Stage 回退。完整 Main Release 性能测量另由主任务执行。

手动打开指定教程，拖动并释放大组，然后一次撤销与重做：成员、连线和文字应恢复到完整操作前后状态。先在属性面板改文字或位置，再开始拖动并撤销：应保留拖动之前的属性编辑。重新加载文档后进行第一次拖动，结果同样应可撤销；取消拖动不应增加历史条目。失败时重点检查外部编辑后捕获了旧基线、加载修订号没有同步，以及无变化事务导致后续撤销冲突。按下 50 ms、释放和历史异步提交帧峰值仍须完整 Main 的正常输入验收。
