# 分组拖动与概览缓存

真实教程 `tutorial-main-3.1.prg`（974 个舞台对象）中拖动“伸缩链”分组，确认概览 CPU 更新为主要瓶颈。原生缩略图的内容键包含全舞台布局/文档版本，因此一个分组移动会反复销毁其他不变分组的 SubViewport、Panel、Label、Line2D，并发起新的 GPU 回读。3 秒采样中，概览刷新累计 1361ms，其中原生缩略图更新 1209ms；暂时停用概览更新的诊断对照将帧耗时中位数从 208ms 降至 67ms。

改为按分组成员维护内容键，复用已有 geometry_version、连线颜色/样式、图片纹理身份和主题状态。成员列表仅在拓扑或预览根集合变化时重建。移动其他分组不再重建不变的缩略图；修改成员位置、文本、颜色、内部连线样式仍刷新所属分组。离开舞台时取消尚未完成的缓存捕获并清理成员索引。沿用 Godot 原生字典、节点、SubViewport 和现有异步捕获流程，没有引入依赖，也没有改变拖动/物理/历史行为。

同条件结果：Godot 4.8-dev6 官方二进制，Intel Iris Xe，Mobile/Vulkan，1996×1248，VSync 关闭，物理开启，缩放 0.284882，加载后预热 1 秒、按下后预热 0.2 秒、连续指针拖动采样 3 秒。测试使用独立 Stage 视口，避免主程序已有实例的启动转发；偏好 UI scale=200，但独立测试控件没有主界面的 UI 缩放布局。

| 指标 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 帧耗时中位数 | 208.401ms | 76.024ms |
| P95 | 264.786ms | 85.396ms |
| P99 | 264.786ms | 89.638ms |
| 采样 FPS | 5.40 | 14.50 |

中位帧耗时降低约 64%，仍未达到 60 FPS；这些是本机开发二进制测量，不能声称是导出 release 或其他设备收益。修复后分组布局还占每帧约 7ms，物理及其他脚本/渲染也仍有开销。未通过降低物理频率、关闭碰撞或降低预览质量获得收益。

验证通过：`group_preview_content_smoke.gd` 的 Headless 与 Mobile/Vulkan，覆盖无关移动保留两组缓存、成员移动只刷新所属分组、成员填充与内部连线颜色更新、静态缓存保留及持久化数据不变；Mobile/Vulkan 的 `async_preview_lifecycle_smoke.gd`；Headless 的 `master_text_colors_smoke.gd`。教程真实指针拖动基准通过，分组实际移动、原文档未修改。基准复制文档到独立 user 临时文件后测试并删除。

现有 `overview_group_geometry_smoke.gd` 的“Root and immediate group previews exist”断言失败；回退到修改前的分组概览脚本复测，七项失败完全相同，未混入其他修复。异步捕获生命周期测试需要图形后端，Headless 等不到渲染信号，已终止该次运行并使用图形后端验证。真实教程加载仍有原有控件锚点警告及一个 ObjectDB 退出泄漏警告。

手动验证：重启项目，打开教程，将视图缩到多个分组显示概览标题，连续拖动“伸缩链”分组。其他分组的概览应稳定，拖动卡顿应明显减轻。释放后确认成员与内部连线跟随；再编辑另一分组的成员文字/填充或内部连线颜色，缩小后应显示新内容。失败时重点检查其他分组缩略图反复闪动、内容修改后概览不更新、成员位置/连线偏移，以及关闭标签时出现纹理错误。

Godot 读写及验证使用 MCP 脚本创建、脚本修改、编辑器脚本执行类别。未执行用户手动验收、导出 release、其他 GPU/系统及长时间内存稳定性测试。
