# 画布撤销的增量恢复

## 改动与原因

旧实现每次撤销都删除并重建整图，单节点修改也会重新实例化全部字体、碰撞、节点和连线。`StageObjectRegistry.restore()` 现在按稳定对象 ID 与类型复用已有实例，只恢复变化的属性和变换，创建缺少的对象、删除多余的对象；完成后统一解析所有引用并保持快照顺序。ID 缺失或重复时保留原有完整重建路径。

复用 Godot 节点、原生 Dictionary/Array、既有序列化和事务快照。评估了内置 UndoRedo：它适合逐动作登记，但迁移当前完整物理事务和引用快照超出这个修复的范围。这里只适配已有快照恢复，不新增历史框架或外部依赖。Godot 文件经 MCP 脚本读取、创建、修改及编辑器脚本执行工具处理。

## 已执行验证

经用户授权运行隔离测试，临时用户数据目录，用户源文档哈希不变。

- 新增 `undo_incremental_smoke.gd`：旧实现不保留实例的断言失败；新实现通过。覆盖文字属性撤销/重做、创建及现有连线重绑、删除恢复、对象顺序、主题父引用、事务取消及历史解锁。
- `local_drag_physics_smoke.gd`：通过，覆盖驱动节点及被避让邻居一起撤销/重做。
- `slice_ungroup_smoke.gd`、`native_dirty_smoke.gd`：通过。
- `canvas_mvp_smoke.gd` 的旧线宽断言失败；恢复修改前的 Registry 后同样失败。本修复未修改线宽行为。
- Godot 脚本解析、提交范围空白检查：通过。

同设备、同版本、同文档、同输入的 release 导出配对测试：Godot 4.8.dev6、Linux X11、Mobile Vulkan、Intel Iris Xe，981 个对象，关闭物理避让，修改一个文本节点后撤销：

| 指标 | 修改前 | 修改后 |
| --- | --- | --- |
| 撤销完成耗时 | 1226.433 ms | 35.091 ms |
| 撤销期间最长帧间隔 | 974.216 ms | 35.090 ms |
| 保留原实例 | 0 / 981 | 981 / 981 |

测量包含恢复等待的帧边界；这是一次配对样本，不是所有图规模的延迟保证。普通属性撤销仍遍历快照，大批量删除的撤销仍需重建被删除的对象。临时 release 测试入口及资源测试后删除，开发项目配置已恢复。

## 用户手动验证（尚未执行）

1. 从当前工作区启动，打开大图，移动或改一个节点，按 Ctrl+Z；应恢复该次操作而无整图清空重建的停顿。按重做快捷键检查操作完整恢复；重点检查漏撤销、对象漂移或历史一直锁住。
2. 创建带连线的新节点，撤销再重做；删除该节点，撤销再重做。应正确恢复/删除节点和连线；重点检查悬空端点、父容器丢失或对象顺序改变。
3. 拖动一个节点触发邻居避让，松开后撤销。节点和邻居应一起恢复，不能在下一物理帧又跳回去。

尚未执行：真实 Ctrl+Z 键盘输入的人工体验检查、最新生产安装包安装、其他平台验证。release 结果来自隔离测试入口。
