# PRG v4 存储交付与验证

实际改动、字节布局、兼容范围与资源限额见 [格式定义](../specs/prg-v4.md)。新增保存默认使用 v4，旧格式保持只读导入；本轮没有批量迁移用户文件，也没有导出或安装新程序。

本轮复用 Godot 原生 Variant、FileAccess、HashingContext 与既有注册表/字体 fingerprint，不新增依赖。Godot 文件使用 MCP 脚本读取、创建、修改及 DirAccess 目录创建类别；普通 Python/Markdown 文件按常规编辑。没有读取场景文本或修改第三方目录。

用户已授权本地测试。Godot 4.8 dev6 下，新增存储回归、625 对象旧 master 教程导入/撤销/保存重开、加载事务均通过；15 个 Python 缩略图测试及 Ruff 检查/格式检查通过。Godot 运行时解析相关脚本通过。旧教程原始归档从已有文件保留块恢复到临时目录，用户文件未改写。

加载响应测试的相机中心断言失败；撤回本次改动后仍出现同一失败，确认属于现有整图居中规则与旧测试不一致。测试启动也报告现有 welcome_card 的 feedback_tween 元数据错误。两项未混入存储提交。尚未执行：GUI 手动验证、性能对比、发布构建、保存故障注入及跨平台验证。

用户手动步骤：

1. 打开旧教程，使用“另存为”生成新的 `.prg`，关闭并重开。应保留文字、位置、完整分组、连线和图片，初始状态干净；失败时检查是否缺对象、图片或引用，以及是否误标未保存。
2. 修改文字、拖动节点并撤销，保存到同一新路径，再关闭重开。内容应正确，并保留 `.previous` 恢复副本；失败时检查第二次保存是否出现保留块/资产偏移失效，以及历史是否丢失。
3. 打开另一份含图片的旧文件，另存为并重开。图片尺寸、格式和显示应一致；失败时重点检查图片块校验、图像解码和复制粘贴后的保存。
4. 使用更新后的 Linux 缩略图工具预览新文件，文字与图片应有离线概览；失败时先确认系统安装的辅助程序已更新，源码修改不会自动更新 `/usr/libexec`。超出离线预览限额的合法文档可能没有缩略图。
5. 对同一内容记录 v3 首次导入、v4 首次打开和 v4 再次打开的耗时，分别记录首屏和可编辑时间；不能把有缩略图提前出现等同于编辑准备完成。

本轮完成的是存储结构切换和几何缓存适配，不是完整节点按需加载/局部物理重构。未经测量不声明加载速度或提速比例。
