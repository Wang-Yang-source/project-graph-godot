# 平移与缩放：连线网格复用

## 改动与依据

连续缩放时，原有屏幕宽度采样会反复改变 `Line2D.scale`、`width` 和 `points`，触发原生网格重建。隔离连线刷新后，大文档缩放帧耗时显著下降；世界曲线和碰撞在导航过程中本来就保持稳定。

复用 Godot 内置 `Line2D`、`ShaderMaterial`、CanvasItem shader 导数与现有视图缓存，不添加依赖。`MultiMesh` 不适合不同曲线及独立拾取；通用对象池不能避免已有连线的网格重建，因此没有引入社区池化库。可见内容仍由节点表达。

- 相机标记连续缩放状态，并在动画结束或进入文本编辑时发出结束信号。
- 连线缩放过程中使用共享材质计算屏幕线宽，保留世界空间网格；网格包络仅在跨越倍率区间或世界几何改变时更新。
- 停止缩放后，在约 60 ms 内分散恢复原有纹理线条；纯平移使用原来的渲染方式。
- 箭头、碰撞、标题路径和持久化数据沿用原来的逻辑。

## 同条件测量

2026-10-03，Godot `4.8.dev6.official.8898c2b3d`，Linux X11，Mobile/Vulkan，Intel Iris Xe，1920×1200，UI 200%，Mailbox，FPS 不限。使用现有 tutorial 文档（981 个对象），关闭物理偏好以隔离导航开销，加载预热 3 秒后，每个阶段采样 3 秒。关闭额外的编辑器运行窗口，编辑器保留；其他桌面程序仍在运行。

| 阶段 | 修改前 FPS | 修改后 FPS | 修改前 P95 ms | 修改后 P95 ms |
| --- | ---: | ---: | ---: | ---: |
| 静止 | 167.43 | 194.76 | 8.445 | 6.395 |
| 平移 | 131.41 | 152.33 | 8.360 | 8.289 |
| 连续缩放 | 54.65 | 75.51 | 42.747 | 22.367 |

缩放 P95 下降约 48%。纯平移代码路径没有改变，其 FPS 差异不能据此归因于优化。静止阶段前后截图逐像素完全一致。以上为本机调试二进制的一次配对测量，不是导出 release 或其他设备的性能保证；缩放 P95 仍高于 60 FPS 的 16.67 ms 预算。

## 已执行检查

所有 Godot 文件读写、测试进程启动及运行窗口停止均通过 Godot MCP 的脚本、编辑器脚本和项目运行控制类别完成。测试使用隔离的 XDG 数据目录，不保存原文档。

- `zoom_stroke_cache_smoke`：Headless、Mobile/Vulkan、Compatibility/OpenGL 均通过。覆盖连续缩放网格复用、恢复原材质、文本编辑中断、延迟恢复期间删除边、碰撞及持久数据不变；有显示后端时检查 shader 的实心部分和透明渐变覆盖。
- `navigation_cache_smoke`、`connection_continuity_smoke` 通过。
- `canvas_antialiasing_smoke`、`hidpi_stage_smoke`、真实文档 `tutorial_navigation_cache_smoke` 在 Mobile/Vulkan 下通过。
- 从 HEAD 单独应用本修复后，新增测试、导航缓存与连线连续性测试通过；提交不包含已有的输入和双向连线改动。
- `pinch_zoom_smoke` 的 “Root pinch reaches canvas exactly once” 与 `reciprocal_connections_smoke` 的反向曲线断言失败，在恢复修改前代码后同样失败。没有把这些已有问题混入本次修复。

## 用户手动验证

1. 重新运行应用，打开同一大文档。Linux 使用 Ctrl/Meta+滚轮或触控板捏合连续缩放，再以中键拖动或双指滚动平移。
2. 应看到连续缩放卡顿减少；停止操作后线条恢复原有样式。重点检查线宽、箭头端点、双向连接、缩到概览再放大后的连线，以及停止缩放时是否出现新的尖峰或闪烁。
3. 缩放过程中进入文本编辑，再返回画布；缩放后移动节点、选择/割线，并撤销重做。连线应跟随节点，碰撞和选择应贴合可见曲线，撤销应恢复完整操作。
4. 如果出现断线、线宽跳变、拾取偏移或恢复时卡顿，记录缩放倍率、主题、显示缩放和涉及的连线类型，重点检查动画状态切换及离屏返回时的材质恢复。
