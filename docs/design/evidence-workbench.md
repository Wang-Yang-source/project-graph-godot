# 设计方案：从材料到有依据的观点图

日期：2026-10-03。状态：指导现有 PRD 实施的设计方案，不是功能完成记录。本次只整理普通文档，没有重新读取 Godot 源码或执行运行验证。论文依据来自仓库既有阅读记录，未新增全文研究或系统综述。

需求正文以 [PRD](../specs/PRD.md) 为准；任务与完成勾选只在 [TODO](../development/TODO.md) 维护；架构边界沿用 [D1–D6](decisions.md)。本方案说明功能为什么需要、如何协同和怎样检查效果，不自动扩大首版范围。

## 1. 核心任务与设计目标

目标用户假设沿用 PRD：独立开发者、研究者及围绕复杂问题阅读材料的人。以约 10–15 份真实材料为验收样例，帮助用户完成：提出问题 → 收集材料 → 组织观点与异议 → 追溯依据 → 重访 → 输出说明。样例数量不是容量承诺。

用户应能解释“我讨论什么、这些内容为什么有关、依据在哪里”。设计应减少重复录入、找原文和维护图的成本。节点数量、边数量或生成文字数量不能直接作为收益指标。

## 3. 共用能力与不同结构的边界

多种图共用创建、文本编辑、选择、移动、连线、分组、复制、历史、保存和导出。复用这些能力，不意味着采用同一套关系推断。

| 结构 | 含义与约束 | 必须避免的混淆 |
| --- | --- | --- |
| 空间包含 | 表示当前位置与分组；沿用单父、无环及既有容器规则 | 靠近或同组不自动表示支持、因果或主题父子 |
| 主题层级 | 为 Tab/Enter 提供明确的主题上下文；多父或环不能误认唯一父主题 | 新增自由关系文字不改变主题创建行为；首版不因此重写旧推导 |
| 通用语义/流程关系 | 可表达支持、异议、分支、汇合、反馈与环 | 不把所有箭头都当成主题边或计算依赖 |
| 因果 DAG 方法模板 | 内容约定为有向无环，配合问题、机制与假设解释 | 不将 DAG 规则强加到所有流程图；反馈图采用不同方法约定 |
| 自动计算依赖 | 由用户明确建立稳定引用；PRD R17 要求检测循环、缺失引用与错误 | 连一条普通边不自动参与计算；LaTeX 排版不自动执行 |

示例：“方案 A”与“成本”处于同一个容器，只说明它们在同一空间区域；“成本限制方案 A”需要关系文字；计算节点读取成本数值则需要单独的计算引用。三者不因视觉上相连而相互转化。

内容访问区分正文、详情、证据与位置、尺寸、外观。首版仍允许一对象一呈现，复用稳定 ID，不创建共享对象库或新的权威数据库。来源记录归所属节点或关系，复制时独立复制。具体约束见 D1/D2/D5。

## 4. 按用户流程组织交互

### 4.1 输入与探索：先表达，再补结构

新建画布先写问题，粘贴材料并用现有快速输入创建节点。节点正文用于短标题或命题，详情用于较长解释。允许未分组节点、空关系文字和不完整来源，不要求创建时填写完整表单。

空间操作服务于整理。物理反馈、容器与线型不改变内容含义；新增反馈通过真实节点表达。稳定阅读与局部布局的后续需求通过重访观察决定，不在本方案中承诺重写物理系统。

### 4.2 表达：关系能读成一句话

例如“保持手工布局 —可能减少→ 重访时的重新定位负担”。选中连线，在已有属性入口编辑自由文字，标签归属连线。移动端点、复制、删除恢复、保存重开后仍可辨认同一关系。

反转操作需检查端点、方向与文字的一致性。系统不能把“支持”自动改写成其他命题，也不由颜色或箭头数量计算论证强度。关系类型建议、自动语义检查不属于首版。

### 4.3 核查：原文与解释分开

复用属性入口，组织为内容、来源、外观三个区域；确切布局遵守既有 UI 规范。来源可挂在节点或关系，保存标题、地址、定位说明、摘录及稳定局部标识。定位说明可手工填写“PDF 第 8 页，方法部分”，地址允许为空；不承诺内嵌 PDF 查看器或页码自动跳转。

修改详情不修改摘录。来源由用户主动打开，失效时保留本地摘录并说明失败；不自动联网抓取。支持多条来源，用户可记录不同依据，不强制去重。

编辑采用草稿。应用一次对应一次用户历史操作；取消保持原内容。切换对象或关闭窗口遇到未应用草稿，提供应用、放弃、继续编辑。新增字段进入既有保存、复制、删除恢复和撤销通路。

### 4.4 找回：搜索结果说明为什么命中

当前画布搜索正文、详情、边文字、来源标题与摘录。同一对象多字段命中合并展示字段和片段，点击按稳定 ID 定位，提供搜索前视野的一步返回。对象删除后刷新结果，不跳到同名对象。

关联列表展示两端、方向、关系文字与来源条数，支持定位。文件名/路径搜索继续使用快速打开；图关联不改称来源库。全库全文检索和全局浏览历史不进入此切片。

### 4.5 输出：保持含义，确认顺序

选择全画布或一个容器导出 Markdown。预览展示本次范围与用户可调整的阅读顺序，关系以两端及文字保存；环、多父关系采用关系表，不强行转为树。保留详情、来源、摘录和对象 ID。

容器展开包含后代与内部连线；显式选中关系纳入两端说明，不沿所有边无限扩张。外部关系统计与画笔遗漏提示沿用 PRD。预览为快照，画布变化后由用户明确刷新；取消不写文件。图片与 SVG 继续承担视觉输出，Markdown 不承诺可回写项目。

## 5. 一次完整任务的设计样例

问题：“编辑器是否应该默认自动布局？”这只是设计样例，不预设答案。

1. 写问题节点，再建两个候选：“默认自动布局”和“用户主动触发布局”。
2. 收集支持与异议，各用短命题作正文，解释与适用条件放详情。通过关系文字说明它挑战哪个具体主张。
3. 在“布局选择应随任务变化”节点记录 H02 的原文定位；在涉及学习效果的主张记录 P18 及限制。不能由这些文献直接推出某个默认设置最优。
4. 多个前提需要联合成立时，用普通文本节点写“联合理由”，分别连入前提再连向结论。这是填图约定，不是自动推理能力。
5. 搜索仅存在于某条摘录中的词，定位到对应对象并返回；通过关联列表读出支持与异议。
6. 保存、关闭重开，确认文字、详情、来源及关系保持；选择问题所在容器，预览并导出可读说明。
7. 几天后根据同一份图解释暂定结论、限制和下一步取证，记录无法解释或找不到的内容。重访记录为用户手工记录，不增加遥测或专用预测模块。

## 6. 实施顺序与复用判断

沿用 TODO 的依赖顺序：T01 命令一致 → T02 加载保护 → T03 保存保护 → T04 恢复入口；随后 T05/T06 内容与关系 → T07 来源 → T08/T09 阅读与搜索 → T10/T11 输出。T14–T20 同属必须交付，按其已有依赖推进；T13 在全部必需能力具备后执行。

实施前先通过规定 MCP 核验现状，再选择最小适配。已有注册表、历史、项目文件、属性/搜索/关联窗口和命令分发为首选复用对象；Godot 字符串匹配、JSON/ZIP、节点控件为原生候选。公式、表达式、快捷键与布局等通用能力先评估原生及社区库，选型结果单独记录，不能把候选写成已兼容。

本方案不新增依赖。后续引入库必须固定版本和哈希、核实许可证及平台/运行时兼容性；候选不适用时先记录理由，再实现必要项目适配。沿用 D6 的暂缓判断，不因新增论文直接引入数据库、全文引擎、同步库或通用解析器。

## 7. 后续指导性功能与进入条件

下表只解释现有暂缓池的研究方向，不新增首版任务或完成勾选。进入开发前需要独立规格、依赖与验收定义。

| 候选方向 | 值得解决的问题 | 进入条件与边界 |
| --- | --- | --- |
| 折叠、锁定、局部布局 | 重访定位、误拖和大图阅读 | 实际任务反复出现负担；定义隐藏与删除、折叠端点和布局撤销规则 |
| 更细的信息层级与摘要 | 总览与证据细节切换 | 定位/阅读观察表明有需求；摘要须能返回原材料，不能覆盖原文 |
| 跨画布引用与全局来源库 | 重复维护相同内容 | 出现持续重复录入；明确共享编辑、独立复制、删除与迁移语义 |
| 自我解释与延迟重建 | 判断用户是否理解关系 | 学习场景明确成立；先用已有模板手工试验，再讨论专用 UI |
| AI 修改提案 | 辅助整理、提出候选关系 | 内容与来源闭环稳定；建议可检查、拒绝、撤销，生成关系不等于事实 |
| 自动保存、同步与协作 | 长期可靠性与多设备工作 | 文件与版本契约稳定后单列规格；论文不能代替冲突和恢复设计 |
