# 实用思维导图样例：论文调查与模板依据

调查日期：2026-10-03。目标：为 Project Graph 提供能直接理解用途、继续编辑的样例内容。此次核查以前讨论的四篇论文，并补充概念图定义的原始技术报告；不是系统综述，不构成对全部文献的效果排序。

**以下模板均为依据研究用途重新组织的项目示例，不是论文原图、实验材料复刻或已验证的教学方案。** 研究结论与项目设计建议分别列出；论文支持某种教学用途，并不等于支持这里的具体布局、颜色或节点数量。

## 1. 先区分思维导图与概念图

思维导图通常从中心主题向外展开分类与子主题，强调层级和空间组织。概念图更强调“概念—关系词—概念”形成可读命题，以及不同分支的交叉关系。判断图的类型应看组织方式和关系含义，不能只看是否使用颜色。Novak 与 Cañas 的原始技术报告也明确允许给概念图调整字体和颜色。[IHMC 技术报告：The Theory Underlying Concept Maps and How to Construct and Use Them](https://cmap.ihmc.us/docs/theory-of-concept-maps)

Project Graph 的样例可以采用树状主结构，并在必要处补充有明确含义的跨分支关系；这是一种适配项目自由图结构的设计建议，不宣称它严格属于某一种教学法。

## 2. 核查的论文与证据边界

### R1：文献组织与写作工作流

- **作者、年份**：Joeran Beel、Bela Gipp、Stefan Langer、Marcel Genzmehr，2011。
- **标题**：*Docear: An Academic Literature Suite for Searching, Organizing and Creating Academic Literature*。
- **出处**：JCDL ’11，465–466 页。[作者提供的论文 PDF](https://docear.org/papers/docear_-_an_academic_literature_suite_--_preprint.pdf)
- **证据**：这是一篇系统演示论文。第 5 节提出用思维导图组织文献集合、批注、引用以及文稿大纲。
- **限制**：未提供验证学习效果或研究效率的对照实验；论文还明确有部分设想尚未实现，不能把整个工作流写成当时已完成的功能。
- **可借鉴之处**：将来源、具体证据和待写内容放在同一结构里，而不是只堆论文标题。

### R2：写作前组织内容

- **作者、日期**：Sena Sebit、Senem Yıldız，2020-10-20。
- **标题**：*Individual and Collaborative Computerized Mind Mapping as a Pre-Writing Strategy: Effects on EFL Students’ Writing*。
- **出处**：*Journal of Computer and Education Research*，8(16)，428–452。[期刊原文与 PDF 入口](https://doi.org/10.18009/jcer.710461)
- **证据**：45 名学生参加准实验，分为个人制图、协作制图和对照组。个人组在各次作文任务的内容与组织评分上较好；协作组的优势出现在第二次任务。
- **限制**：研究针对外语写作，不能推定对所有语言、年龄或写作任务都有效。标题用 mind mapping，摘要多处用 concept mapping，术语存在混用。
- **可借鉴之处**：先组织观点与证据，再转成段落；本项目额外加入反对意见与回应，是论证写作的模板设计，不能归为该实验的具体材料。

### R3：知识复习与实际学生导图

- **作者、日期**：Anthony V D’Antoni、Genevieve Pinto Zipp、Valerie G Olson、Terrence F Cahill，2010-09-16。
- **标题**：*Does the mind map learning strategy facilitate information retrieval and critical thinking in medical students?*
- **出处**：*BMC Medical Education*，10，61。[出版商全文，含 Figure 2](https://doi.org/10.1186/1472-6920-10-61)
- **证据**：131 名一年级医学生参加研究，导图组接受 30 分钟介绍。Figure 2 是参与者制作的真实导图，使用放射层级、颜色和图片。
- **限制**：研究未发现导图提高短期知识回忆或批判思维；正文对文本知识测验（记忆测验）的标准化前后测差值分析甚至偏向普通笔记组（p = .027），这个数值不是批判思维 HSRT 的结果。不能只摘取“没有劣势”，也不能以样例好看作为提高记忆的证据。研究对象是初学者，结果不能回答长期熟练使用后的效果。
- **可借鉴之处**：主题层级能帮助观察知识覆盖，但复习模板应加入使用者自己回答的问题，避免只做排版。

### R4：小组任务与信息完整性

- **作者、日期**：Jieyu He、Bei Wu、Haiying Zhong、Junkun Zhan、Lanyan Zhu、Jie Zhang、Yi Zeng、Zhihong Li，2024-03-26。
- **标题**：*Implementing mind mapping in small-group learning to promote student engagement in the medical diagnostic curriculum: a pilot study*。
- **出处**：*BMC Medical Education*，24，336。[出版商全文](https://doi.org/10.1186/s12909-024-05318-0)
- **证据**：86 名预防医学本科生在小组课程中使用导图，覆盖体格检查、心电图解读和病史采集。部分使用更充分或导图更深入的小组，在相应考核和信息完整性上表现较好。
- **限制**：试点研究存在班级基础差异、使用程度差异和额外平时分激励；一年后的总成绩及 OSCE 未出现明显收益，后续临床跟踪不足。因此不能把关联解释为普遍因果效果。
- **可借鉴之处**：用共同结构检查任务缺项。下面将这种用途迁移到一般问题分析，不提供临床诊断模板。

## 3. 四种项目改编模板

| 模板 | 具体起点 | 主要分支 | 结束时要得到什么 | 依据 |
| --- | --- | --- | --- | --- |
| 文献综述 | 一个可回答的研究问题 | 观点、方法、证据、局限、研究缺口 | 每个判断都有来源，能看到矛盾和空缺 | R1 工作流 |
| 写作论证 | 一个需要论证的主张 | 背景、分论点、证据、反对意见、回应 | 可转成正文的论证顺序 | R2 写作前组织；其余为项目扩展 |
| 知识复习 | 一个章节或主题 | 概念、机制、分类、例子、易混点、自测 | 使用者能脱离原笔记解释关系 | R3 组织形式；自测为项目扩展 |
| 问题分析 | 一个真实但尚未解决的问题 | 现象、已知事实、可能解释、区分证据、下一步 | 区分事实与假设，明确还缺什么 | R4 信息完整性用途的迁移 |

### A. 文献综述：思维导图何时有用？

中心问题：**思维导图何时有用？**

- 写作组织 → R2 → 内容与组织评分 → 适用边界：外语写作。
- 知识回忆 → R3 → 未发现短期优势 → 待问：训练与长期效果。
- 文献工作流 → R1 → 文献、批注、草稿 → 边界：工具演示。
- 小组任务 → R4 → 部分技能与完整性 → 边界：试点与混杂因素。
- 综合判断 → 选择任务，再选择结构 → 不预设导图总比笔记好。

跨分支关系示例：R3 的“未发现短期优势”连接到“综合判断”；R4 的“信息完整性”连接到“问题分析”。关系词可写在说明节点内，是否支持线标签须另行核查项目实现。

### B. 写作论证：为什么先组织，再写正文？

中心主张：**写作前先把观点和证据摆出来。**

- 读者与问题 → 面向谁 → 要解释什么。
- 核心理由 → 内容更完整 → 顺序更清楚。
- 可用证据 → R2 外语写作研究 → 明确样本与适用范围。
- 反对意见 → 制图也耗时 → 熟悉结构的人未必需要。
- 回应与边界 → 小型提纲即可 → 按任务选择。
- 正文顺序 → 问题 → 理由 → 证据 → 限制 → 行动。

样例中的“反对意见”和“回应”是写作练习提示，不代表论文已经测量了制图时间成本。

### C. 知识复习：学会区分两种图

中心主题：**思维导图与概念图。**

- 思维导图 → 中心主题 → 分支与层级。
- 概念图 → 概念 → 关系词 → 命题。
- 共同用途 → 组织信息 → 观察关联。
- 易混点 → 彩色不等于思维导图 → 树状不等于完整解释。
- 自测 → 这条连线表达什么？ → 能否举一个反例？
- 资料 → IHMC 报告 → R3 的 Figure 2。

这是一个非医疗的知识样例。自测分支是项目作者的练习设计，未由 R3 单独验证。

### D. 问题分析：为什么打开大项目很慢？

中心问题：**为什么打开大项目很慢？**

- 现象记录 → 打开时等待较长 → 何时开始、何时完成？
- 待收集事实 → 文件大小 → 对象数量 → 设备与版本。
- 可能解释 → 文件读取 → 对象创建 → 关系解析 → 首次显示。
- 区分证据 → 分阶段耗时 → 小项目对照 → 重复打开对照。
- 下一步 → 先定位最长阶段 → 再选择对应优化。
- 待确认 → 优化前后是否改善 → 保存与重开是否完整。

这些现象、假设和检查项均为演示内容，不是本项目的实测结果。将“可能解释”与“待收集事实”分开，避免把猜测写成结论。执行耗时测量或运行验证仍需用户授权。

## 4. 视觉与可编辑性建议

这些是项目设计判断，没有声称来自论文实验：

- 每张图只保留一个明确主题，首层控制在四至六个分支；缩略图能读到主题，进入画布后能读到证据和限制。
- 优先使用项目已经具备的节点、关系与容器表达内容，不增加仅为样例需要的新型对象。
- 用空间、字号和少量语义颜色形成层级；颜色之外保留文字角色，如“证据”“假设”“待确认”。
- 主要分支保持足够间隔，长段落拆为结论与来源两个节点；不要把来源藏进难以看到的装饰文字。
- 一张图保留少量必要交叉关系，让线能说明实际含义；避免为了显得复杂而堆叠连线。
- 示例应含真实但简短的已填内容，使用户知道如何续写；另保留“换成你的问题”等编辑入口。
- 论文原图只通过来源链接提供。本次没有下载或复制论文图片，也没有新增图形或图布局依赖；样例组织直接采用现有项目方式。

## 5. 手动核查方法

调查文档及四组 `.prg` 模板、SVG 设计预览与 PNG 实际渲染图已制作完成，入口、文件与操作方法见[样例模板交付说明](../examples/mind-maps/README.md)。后续经用户授权完成原生加载、引用、布局、保存恢复及实际渲染检查，详见[验收记录](../validation/mind-map-templates.md)。完整应用窗口中的手动交互流程尚未执行；研究整理本身没有运行项目或测试。

用户核查文献时，打开 R1 第 5 节、R2 摘要、R3 Figure 2 与 Results、R4 Methods 与 Limitations，检查证据是否对应这里的描述。重点检查是否把试点、无显著优势或工具演示误写成普遍有效。

用户核查样例时，从项目中实际提供的模板入口打开相应图，依次缩放、移动节点、改写问题并保存后重新打开。应观察到主题层级清楚、文字完整、连线指向正确、来源与限制保留。失败时先检查节点重叠、截断、关系端点脱离对象以及重开后的内容缺失。具体入口与可用交互以实际模板交付说明为准。
