# 落地案例：从材料到推理，再从结果修订

日期：2026-10-03。以下案例说明怎么填图。案例 A 对应当前目标，研究材料是真实文献，但个人使用结果尚未取得；案例 B 的数值全部为教学假设，不是项目日志或实际性能数据。每次只启用一个主框架和一个审查框架。

## 案例 A：网状图能否帮助我检验自己的思考？

**主框架 M05 论证网，审查框架 M06 批判审查。** 原生图见 [完整案例](maps/02-worked-example-thinking-audit.prg)。

### 1. 先定义目标

不是“我画出了多少节点”，而是我能否发现并修正具体的证据不足、推理跳跃、隐藏前提、替代解释及行动条件。此定义是本次使用约定，不是心理学量表。

暂定主张：值得做一次有限试用。成立条件：关系必须可解释，证据和解释分开，主动寻找反例，并根据结果修订。不能预填“已经提高思考能力”。

### 2. 文献进入的是哪条推理？

[P14 的原文](../papers/argumentation/2018-cullen-argument-visualization.pdf)研究了 12 周论证可视化课程，课程同时有练习和反馈。它提供“显式组织和反复修订论证可能有帮助”的线索，但不能推出当前软件、这套模板或某个使用者一定受益。

[P07](../papers/learning/1989-chi-self-explanations.pdf)讨论例题学习中的自我解释，可用于提醒自己解释每一步的依据。它不是网状图软件实验。图画得漂亮、拥有跨分支边和阅读时觉得理解，都不能代替独立解释与新任务表现。

候选保证：如果我必须把“材料怎样推出主张”写出来，就更可能注意到原先省略的条件。**这是用于设计此次使用过程的假设**，仍需要个人任务记录。

### 3. 接上真正的反驳

| 异议 | 挑战对象 | 如何处理 |
| --- | --- | --- |
| 改善来自更多时间或阅读，而不是网状表达 | 关于方法效果的解释 | 记录时间、资料数量和任务难度；不把所有改变都归于图 |
| 复杂图也可能只是重复确认偏见 | 保证的成立条件 | 强制寻找一个合理的替代解释和一个能推翻主张的观察 |
| 很多引用实际上来自同一研究 | 证据独立性 | 将转载与共同原始数据记在同一来源链上 |
| 别人图中结论可解释，不代表我已经掌握 | 学习收益 | 离开图复述关键关系及条件，再处理新问题 |

这里“强制寻找一个”是启动动作，不是声称找到一个反例就完成了所有审查。

### 4. 一次有限使用怎么做？

1. 选一个尚未定论的真实问题，先保存普通笔记版本：问题、结论、依据和用时。基线现在为空。
2. 用 M05 填主张、资料、保证、支撑、限定和例外；将实际任务来源与方法文献分开。
3. 用 M06 审查术语、假设、独立性、遗漏和对称标准；将异议接到对应节点。
4. 写下一项会改变判断的观察或行动；不要只新增一圈方法名。
5. 离图解释：材料凭什么支持主张、最强反例是什么、哪些条件不满足就要改判。
6. 记录具体发现及修订。随后再选新任务检查迁移；需要学习持久性信息时另设延迟复查，不同时展开很多框架。

这是一份供用户实施的方案，**本次没有执行该试用**。任务难度、练习和顺序可能影响结果；个人记录可支持“对我在这个任务中有何作用”的判断，不能直接产生因果效果或普遍结论。

### 5. 如何收束？

| 观察 | 接下来的动作 |
| --- | --- |
| 能解释连线，并发现此前未注意到的前提 / 反例 | 保留相关结构，换新问题检查是否可迁移 |
| 只是增加文字或增加支持链接 | 删除没有解释作用的节点；回到资料、保证和反例 |
| 各种方法名称挤在一起，没有具体问题 | 只保留 M05 主框架与 M06 审查；方法总图用于导航 |
| 严重遮挡或连线难以追踪 | 分成任务子图，用具体问题连接；不把更多节点当成更深思考 |
| 无法判断收益 | 保留“未知”，继续记录或停止投入，不能预填成功 |

## 案例 B：告警出现，就说明故障了吗？

**主框架 M09 概率更新，审查框架 M06 批判审查。** 所有数字为教学设定。

设 H 表示设备确有故障，E 表示出现告警。假设该参考类中故障率 1%；有故障时 90% 会告警；无故障时 10% 也会告警。问题是 `P(H|E)`，不是 `P(E|H)`。

| 节点 | 填入内容 | 所属角色 |
| --- | --- | --- |
| 参考类 | 同一类设备、同一时间窗，故障率 1% | 材料 |
| 先验 | P(H)=0.01 | 推理 |
| 真阳性率 | P(E\|H)=0.90 | 推理 |
| 假阳性率 | P(E\|非H)=0.10 | 推理 |
| 新证据 | 看到了告警 E | 材料 |
| 后验 | 0.009 / (0.009+0.099) ≈ 8.33% | 推理 |
| 来源疑问 | 这些率是否来自当前设备？有没有时间漂移？ | 质疑 |
| 证据依赖 | 第二次告警是否来自同一传感器误差？ | 质疑 |
| 行动阈值 | 检查成本、漏检代价和停机代价是什么？ | 界定 |
| 下一步 | 取独立检测信息，或按实际代价立即检查 | 行动 |

直观频率解释：10,000 个设备中，100 个故障，约 90 个告警；9,900 个正常，约 990 个也告警。1,080 个告警中约 90 个真故障，比例约 8.33%。不能因为 90% 的故障会告警，就说告警后有 90% 的故障概率。

关键网状连接：参考类约束先验；真阳性率和假阳性率共同约束证据诊断性；后验与误判代价共同决定行动；独立性限制后续证据更新。**8.33% 不是“无需检查”的结论**，还需要故障代价与检查成本。

失败自检：若直接写出 90%，回查条件概率方向；若两次同源告警被独立相乘，回查证据依赖；若用一个数直接决定行动，回查价值和代价。此案例不构成真实设备的诊断建议。

## 记录一次思考过程

| 字段 | 你要填的内容 |
| --- | --- |
| 问题与日期 | 对象、范围、截止时间 |
| 主框架 / 审查框架 | 最多两个，解释各自解决哪个缺口 |
| 事前判断 | 结论、适用条件、信心或概率 |
| 独立材料 | 来源、定位、取得方式、共源关系 |
| 推理保证 | 从资料到结论需要什么规则 |
| 最强异议 | 挑战资料、规则、条件还是价值 |
| 改判条件 | 哪项观察会改变判断 |
| 实际行动与结果 | 事实、缺失与解释分开 |
| 修订 | 原判断、新判断与原因 |
| 待复审 | 时间 / 信号，以及剩余未知 |

这份记录用于追踪理解与改变，不形成自动评分，不把没有填写的项默认为通过。
